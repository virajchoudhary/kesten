Select exact current patches and resolve scientific/beat compatibility in a disposable environment before implementation acceptance. Official-documentation compatibility is not a successful repository install.

## Decisions only the owner can settle

Choose a brand concept or request a different direction. Confirm the intended launch jurisdiction, legal entity, and whether the R1 audience/scope is acceptable. Approve or revise the architecture and phased plan. These are the immediate approval decisions; the proposed defaults make the choices concrete without silently committing the owner.

Trademark similarity searches, data rights, a commercial business model, retention policy, provider choice, and actual spending remain unresolved. They need owner or professional review before their corresponding external action. They do not require a discovery rewrite or speculative implementation now.

## Approval boundaries

Approving this package may authorize only the selected implementation phases. It does not rename the GitHub repository, purchase domains, create accounts/subscriptions, train on paid infrastructure, deploy, migrate production data, publish recommendations, or assert certifications. Each such action needs the separate authorization already required by the user.

No major existing module has been deleted, renamed, or rewritten. The retired product names remain in legacy code as historical implementation identifiers. They are not proposed public brands. A new public brand must pass legal and purchase checks before external use.
